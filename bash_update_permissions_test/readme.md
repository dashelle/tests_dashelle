Filesystem Security Degradation Tool (Test Environment)

**Назначение**

Данный скрипт - эксперимент предназначен для **контролируемого намеренного нарушения (degradation) безопасности файловой системы операционной системы в тестовом окружении** в рамках **internal security testing**.

Он используется для:
- проверки механизмов контроля целостности
- тестирования реакции ОС на изменение прав/владельцев системных файлов
- негативного (negative) и fault-injection тестирования
- оценки устойчивости security-контуров

**НЕ для production.**
⚠️ **Использовать ТОЛЬКО в изолированной тестовой среде.**
Например, VM, VB, Docker
Рекомендуется сделать snapshot-based окружение
❌ НЕ использовать:
production
shared environments
хост-системы

---

**Что именно тестируется (WHY)**

Скрипт позволяет проверить, ломаются ли или детектируются ли:

- контроль целостности файлов (AIDE, IMA, tripwire и аналоги)
- механизмы hardening (permissions, ownership expectations)
- реакции systemd / init-сервисов
- безопасность cron / profile / shell init
- поведение SELinux
- реакции monitoring / audit систем
- корректность rollback / recovery процедур

Идея: **ОС должна либо задетектить изменения, либо деградировать предсказуемо**.

---

**Принцип работы (WHAT)**
1. Берёт список чувствительных системных файлов и директорий
2. Массово изменяет:
   - владельца (chown)
   - права доступа (chmod)
3. Делает это:
   - контролируемо
   - воспроизводимо
   - по заданному сценарию
4. Позволяет:
   - экспортировать сценарий
   - зафиксировать состояние после «ломки»

---

**Почему не вручную (WHY NOT MANUAL)**

Ручное изменение прав:
- плохо воспроизводимо
- трудно документируется
- легко сделать случайную ошибку
- сложно использовать в регрессии

Скрипт решает это:
- одинаковые сценарии
- фиксированный input
- предсказуемый output
- пригоден для автотестов

---

**Ограничения и преднамеренные решения**

❗ **Намеренные ограничения**

* запрещены chmod "000" и "0000"
  - чтобы ОС не становилась полностью неуправляемой
* каталоги не обрабатываются без "-R"
  - чтобы избежать случайного каскадного разрушения
* "--create" требует явного "--chown"
  - исключает неявное загрязнение системы

---

**Типовые сценарии тестирования:**

**Нарушение прав системных файлов**
sudo ./script.sh --import=files.txt --chmod=644

**Нарушение владельцев**
sudo ./script.sh --import=files.txt --chown=root:users

**Массовая деградация**
sudo ./script.sh --import=files.txt --chmod=755 --chown=root:root -R

**Проверка реакции ОС**
sudo ./script.sh --import=files.txt --chmod=644 --report

**Импорт**
Файл импорта - описание поверхностной атаки (список манипулируемых файлов передаётся в MASSIVE_FILES, см. скрипт)
Каждая строка — путь, чувствительный для безопасности ОС:
/etc/passwd
/etc/shadow
/etc/profile.d/*
/var/spool/cron/

**Экспорт** 
позволяет фиксировать сценарии атаки, регрессию
